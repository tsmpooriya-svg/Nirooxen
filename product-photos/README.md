# عکس‌های خانواده که در مخزن کد نگه داشته می‌شوند

پوشهٔ `photos/` عمداً در `.gitignore` است: آنجا فضای کار اپراتور است و هر چیزی
ممکن است داخلش باشد. این پوشه فرق دارد — عکس‌هایی که **انتخاب و تأیید شده‌اند**
و باید با کد سفر کنند، تا روی هر سرور با یک `git pull` در دسترس باشند و معلوم
باشد کدام نسخه کِی اعمال شده است.

نام هر فایل، کلید خانواده در `photo-plan.json` است.

## اعمال

    npm run photos:plan            # نقشه را تازه کن (اگر کاتالوگ عوض شده)
    npm run photos:apply:repo              # پیش‌نمایش — چیزی نوشته نمی‌شود
    npm run photos:apply:repo -- --apply   # اعمال

`photos:apply:repo` فقط `PHOTOS_DIR` را به همین پوشه می‌دهد؛ بقیه‌اش دقیقاً
همان `photos:apply` است.

سه تای اول از رندرهای برند خودمان‌اند (پس‌زمینهٔ نقشه‌کشی) و دوتای آخر عکس
استودیویی با پس‌زمینهٔ سفید. خط لوله خودش تشخیص می‌دهد کدام چطور روی قاب
بنشیند؛ چیزی دستی تنظیم نمی‌شود.

بقیهٔ خانواده‌های این دسته مخزن پلی‌اتیلن نیستند و عکس جدا می‌خواهند: تیوپ
منبع تحت فشار، منبع دیافراگمی، منبع درجه‌دار، مخزن کتابی، مکعبی، زیرپله و
کروی.

## چرا webp و نه فایل اصلی

سه عکس اول PNG بودند و مجموعاً ۴ مگابایت؛ به webp با کیفیت ۹۵ که تبدیل شدند
۳۳۰ کیلوبایت شدند. اختلاف خروجی نهایی با مسیر PNG اندازه‌گیری شد: به‌طور
میانگین ۱ واحد از ۲۵۵ — یعنی دیده نمی‌شود. فایل اصلی PNG دست صاحب سایت است و
اگر روزی لازم شد، همین‌جا جایگزین می‌شود.
